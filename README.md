# mihomo: выбранные программы через прокси из подписки

Служба Windows на ядре [mihomo](https://github.com/MetaCubeX/mihomo) (бывший Clash.Meta).
Весь трафик машины проходит через виртуальный адаптер (TUN), но через прокси уходят
только указанные программы (по умолчанию `Claude.exe` и `claude.exe`), остальное идёт напрямую.
Серверы берутся из подписки, которую mihomo сам скачивает по расписанию и подменяет на лету,
без перезапуска: адаптер не пересоздаётся, SSH-сессии и прочие долгие соединения не рвутся.

## Как устроено

```
subscription.txt + config.template.yaml --> core\build-config.ps1 --> core\config.yaml --> служба mihomo
                                                                                              |
                           подписка скачивается самим mihomo каждые 3 часа <------------------+
```

| Файл | Назначение |
|---|---|
| `service.bat` | Меню управления: установка службы, запуск, лог, обновление подписки, задержки серверов |
| `config.template.yaml` | Шаблон конфига mihomo. Здесь правила (какие процессы через прокси), фильтр серверов, интервалы |
| `subscription.txt` | Ссылка на подписку, одной строкой. В git не попадает (образец: `subscription.example.txt`) |
| `core\build-config.ps1` | Подставляет ссылку в шаблон, сохраняет `core\config.yaml`, проверяет его `mihomo -t` |
| `core\get-binaries.ps1` | Скачивает `mihomo.exe` (сборку с патчами из Releases этого репозитория) и WinSW (`mihomo-service.exe`) |
| `patches\` | Патчи к исходникам mihomo, см. «Ядро с патчами» |
| `.github\workflows\build-core.yml` | Сборка ядра с патчами в GitHub Actions и публикация в Releases |
| `core\mihomo-service.xml` | Описание службы для WinSW: автозапуск, перезапуск при падении, ротация логов |
| `core\status.ps1` | Состояние службы, подписки и выбранного сервера; `-All` прогоняет все серверы |
| `core\reload.ps1` | Команды работающей службе через API: перечитать конфиг, обновить подписку |

Рабочие файлы mihomo (`core\providers\`, `core\ui\`, `core\logs\`, `core\cache.db`) в git не попадают.

## Установка

1. Скопируйте `subscription.example.txt` в `subscription.txt` и вставьте ссылку на подписку.
2. Запустите `service.bat` (попросит права администратора), пункт **1**.
   Бинарники скачаются сами, конфиг соберётся и проверится, служба установится и запустится.
3. Через минуту откройте панель: пункт **9** или http://127.0.0.1:9090/ui.

Если на машине ещё работает служба sing-box из соседнего проекта, сначала в её `service.bat`
выключите автообновление (пункт 9, иначе задача планировщика продолжит качать подписку каждые 3 часа)
и удалите службу (пункт 5): два TUN-адаптера и два API на порту 9090 не уживутся. Пункт 1 это проверяет.

Если после установки перестали открываться сайты, значит mihomo не смог взять системные DNS
(`dns.nameserver: system`). Впишите туда адрес роутера или публичный резолвер
(например `1.1.1.1`) и выполните пункт 4.

## Повседневное

- **Состояние**: в шапке `service.bat` видно, работает ли служба, сколько серверов в подписке,
  когда она обновлялась, до какого числа оплачена и какой сервер выбран сейчас.
- **Правки конфига**: редактируйте `config.template.yaml`, затем пункт **4**. Конфиг пересоберётся
  и подхватится без перезапуска службы. Адаптер пересоздаётся только если менялся раздел `tun`.
- **Обновить подписку сейчас**: пункт **7**. По расписанию mihomo делает это сам
  (`proxy-providers.sub.interval`, секунды; по умолчанию 10800, то есть 3 часа).
- **Задержки серверов**: пункт **8**.
- **Лог**: пункт **6**. Уровень `log-level: warning`; при `info` mihomo пишет каждое соединение,
  и лог растёт на десятки МБ в день (ротация 5 МБ × 3 файла всё равно включена).

## Что настраивать в config.template.yaml

- **Какие программы через прокси**: раздел `rules`, строки `PROCESS-NAME,<имя.exe>,proxy`.
  Имя процесса видно в диспетчере задач на вкладке «Подробности».
- **Фильтр серверов**: `proxy-providers.sub.exclude-filter`, регулярное выражение Go по имени сервера.
  По умолчанию исключаются российские.
- **Выбор сервера**: группа `proxy` типа `url-test` берёт самый быстрый; `tolerance` (мс) не даёт
  прыгать между близкими по задержке серверами.
- **DNS**: всё через системные резолверы, а домены `anthropic.com`, `claude.ai`, `claude.com`
  через DoH 1.1.1.1 поверх прокси (`dns.nameserver-policy`). Разделить DNS по процессу mihomo не умеет,
  поэтому список доменов задаётся вручную.

## Локальный прокси для других программ

На 127.0.0.1:7890 открыт HTTP- и SOCKS5-прокси (`mixed-port`). Всё, что пришло на этот порт,
идёт через прокси (правило `IN-PORT,7890,proxy`), так что любую программу можно пустить
через подписку, указав ей прокси 127.0.0.1:7890. Можно выставить его и системным прокси Windows,
сам mihomo этого не делает. Проверка:

```bat
curl -x http://127.0.0.1:7890 https://www.gstatic.com/generate_204 -o nul -w "%{http_code}"
```

## Ядро с патчами

Официальный mihomo не подключается к части серверов подписки, поэтому используется своя сборка:
те же исходники [MetaCubeX/mihomo](https://github.com/MetaCubeX/mihomo) и два небольших патча из `patches\`.

- **`reality-client-version.patch`.** В рукопожатии REALITY клиент сообщает серверу свою версию.
  У mihomo она захардкожена как 1.8.2, а серверы Xray-core v26.7.11+ по умолчанию пускают только клиентов
  не старше 26.3.27 (`minClientVer`) и остальным молча отдают настоящий сайт: в логе
  `REALITY authentication failed`. Патч подставляет номер последнего релиза Xray на момент сборки.
  Разработчики mihomo исправлять это отказались (MetaCubeX/mihomo#3132, #3339).
- **`grpc-alpn.patch`.** Часть gRPC-серверов согласует ALPN `http/1.1` или не согласует его вовсе,
  хотя говорит по HTTP/2. mihomo на этом рвал соединение (`http2: unexpected ALPN protocol http/1.1, want h2`),
  а xray и sing-box работают. Патч ведёт себя так же, как они.

Третья причина не требует патча и решается в `config.template.yaml` (`proxy-providers.sub.override`):
для gRPC с пустым `grpc-service-name` mihomo идёт на путь `/GunService/Tun`, а серверы xray ждут `//Tun`.

Собирает ядро GitHub Actions (`.github\workflows\build-core.yml`). Сборка запускается раз в сутки,
если у MetaCubeX вышел новый релиз, после изменения патчей и вручную. Результат публикуется в Releases этого репозитория
с тегом `core-v<версия>`: архив `mihomo-windows-amd64-compatible.zip` и его SHA-256.
`core\get-binaries.ps1` скачивает оттуда последнюю версию и сверяет контрольную сумму, поэтому Go на машине не нужен.
Если новая версия mihomo сломает патч, сборка упадёт с письмом от GitHub, а прежние релизы останутся.

Официальное ядро без патчей: `core\get-binaries.ps1 -Force -Upstream -MihomoVersion 1.19.33`.
mihomo распространяется под GPL-3.0, а исходники сборки — это его тег плюс патчи из этого репозитория.

## Известные ограничения

- DNS по процессу не разделяется, домены Claude для DoH через прокси перечислены вручную (см. выше).

## Обновление mihomo

Остановите службу (пункт 3), запустите `core\get-binaries.ps1 -Force` (возьмёт последнюю сборку из Releases,
конкретную версию можно задать `-MihomoVersion 1.19.33`), запустите службу (пункт 2).
